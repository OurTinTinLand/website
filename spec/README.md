## 1\. 项目背景与目标



- TinTinLand：2018 年创立，华语最大 Web3 开发者社区，2026 年开始拓展 AI 方向业务。

- 核心资产：30 万\+ 开发者、220\+ 高校、50\+ 公链官方合作、800\+ 项目孵化、累计发放奖励 $370万\+。

- 2026 年新业务线（本次官网必须承接）：课程（FDE / AI 短剧 / AI 应用等）、企业服务（AI 转型咨询）、Token Hub（AI 大模型 token 代理/分销，**已有明确合作渠道商**）、代理云厂商产品分销。

- 官网核心目标：**让第一次来访的人在 10 秒内看懂"我是谁、这里能给我什么、下一步点哪里"**，同时把过去分散在 B站/YouTube/Luma/Notion 的历史内容和未来的新内容统一到官网入口。

- 视觉基调：品牌资产目前基本空白，本次项目**顺带完成品牌视觉的第一版**（Logo、吉祥物、配色规范），不是等品牌做完才开始开发，而是设计师和开发并行推进（见第 3 章协同机制）。

## 3\. 一周落地机制：设计师与开发如何并行，不互相卡进度



这是本项目能不能一周做完的关键，单独拿一章说清楚。



**核心原则：设计师"抢跑"半天到一天，用最小可交付单位喂给开发，不要等"全套设计规范"做完才给。**



推荐节奏：



|时间|设计师产出|开发承接的动作|
|---|---|---|
|D1 上午|3 个配色方案草图 \+ Logo 文字方案（哪怕先是纯文字排版），敲定一个|开发先搭项目骨架、路由、导航栏结构，用系统默认灰色调过渡|
|D1 下午\-D2|敲定的配色出成 Design Token（背景色/主色/文字色/圆角/间距的具体数值，一张表就行，不用整套 Figma 组件库）|开发把 Design Token 接入 Tailwind 配置，全站换色|
|D2\-D3|胖狗吉祥物草图（3 个静态表情：默认/眨眼/打招呼即可，不强求动画）|开发先用几何图形占位（比如一个圆形\+简单表情）接入悬浮球逻辑，等吉祥物图出来直接替换图片，不改代码结构|
|D3\-D5|各板块卡片视觉细化（课程卡/活动卡/黑客松卡样式）|开发这几天在做数据结构和列表/详情页逻辑，卡片视觉随时可以插进去，不影响功能开发|
|D5\-D7|补细节、走查、动效微调|开发收尾、测试、部署|



**关键要求**：吉祥物动画**第一版可以不做**，用静态图 \+ CSS 简单过渡（呼吸感用 CSS 缩放动画就够，不需要 Lottie），这样不会因为等动画素材卡住开发主线。动画效果留在 V1\.1 用 Lottie 升级。



**本周目标**：设计师本周产出的是"够用的第一版视觉规范"，不是最终品牌手册；开发不因为等设计而空转超过半天。

## 5\. 首页设计：假 AI 对话路由（V1 核心亮点）



### 5\.1 为什么先做"假 AI"而不是接真大模型



一周时间，接真实大模型意味着要处理 prompt 设计、上下文管理、失败兜底、内容安全过滤等一整套工程问题，风险极高。**"假 AI"本质是一套规则引擎 \+ 预设话术库**，用户体验上依然是"打字或点选项→立刻给出结构化答案和行动按钮"，只是背后没有大模型推理，而是关键词匹配 \+ 预置的意图卡片。这个方案能在 1\-2 天内做完，且**代码结构和真 AI 接口保持一致**，V1\.1 换成真大模型时只需要替换后端逻辑，前端不用重做。



### 5\.2 交互设计



```Plain Text
┌──── Hero（首屏） ─────────────────────────────┐
│         [胖狗 TinTin 静态图，打招呼姿势]           │
│                    │
│                                                │
│    ┌──────────────────────────────────┐       │
│    │ 点下面的快捷指令，或者直接打字告诉我你想干嘛——学东西、打黑客松、找工作、买大模型 token，我都能给你指路。

│    └──────────────────────────────────┘       │
│                                                │
│  [推荐一门课] [最近黑客松] [找生态工作]           │
│  [买 Token] [随便看看]                    │
└────────────────────────────────────────────────┘
```




![image\.png](图片和附件/image.png)



- 用户点击任一 chip 或输入包含关键词的文字（比如"课程""学习""AI"→ 匹配课程意图；"黑客松""比赛""奖金"→ 匹配黑客松意图；"工作""招聘""岗位"→ 匹配招聘意图；"token""充值""大模型"→ 匹配 Token Hub 意图）；

- 匹配后**直接返回结构化卡片**：一句话说明 \+ 1\-2 个具体推荐内容（比如具体某门课）\+ 明确的行动按钮（"报名这门课" / "查看黑客松详情"），不是泛泛的"了解更多"；

- 无法匹配到任何关键词时，兜底话术："这个我还没学会，你可以直接看看下面这些板块，或者留言联系我们的团队"，附上四个板块入口和联系表单链接；

- 首屏下方保留 4 个身份分流卡（开发者 / 项目方 / 求职者 / 随便看看），给不想打字的用户一个更直接的路径，点击后同样触发对应的规则匹配结果。

    

### 5\.3 全站悬浮TinTin狗



- 除首页外的其他页面，右下角常驻一个胖狗头像悬浮球（V1 用静态图 \+ CSS 呼吸动效，不用等动画素材）；

- 点击展开一个简化对话面板，复用首页的同一套规则引擎，让用户不管在哪个页面都能问"怎么报名""怎么充值"这类问题；

- **本周目标**：假 AI 路由能覆盖课程/活动/黑客松/招聘/Token Hub 五个核心意图 \+ 一个兜底方案；悬浮球在所有页面正常展开/收起。V1\.1 目标：换成真实大模型 \+ 上下文记忆。

## 6\. 登录方案：三选一，零填表



**首次注册/登录只提供 3 种方式，且都做到几秒内完成，不要求填写任何额外资料，不注册也可以浏览，但跟平台有交互，比如与AI对话需要登陆许可：**



|方式|交互|本周优先级|
|---|---|---|
|邮箱验证码|输入邮箱 → 收验证码 → 直接登录，不设密码|**必须做，本周主力方案**|
|微信一键登录|扫码/跳转授权|本周做，如果微信开放平台资质/审核来不及，先做 UI 入口，接口留空放 V1\.1|
|Web3 钱包签名登录|连接钱包签名一次，无需转账无 gas|本周做基础版（MetaMask 一种钱包即可），放在邮箱下方的小字链接，位置低调|



**明确不做的事**：注册环节不要求手机号、不要求实名、不要求填职业/公司。这些信息挪到"报名课程/活动/黑客松/投递简历"的那一刻才通过场景化表单收集，一次填写后写入用户档案，下次自动带出。



**本周目标**：邮箱验证码登录必须跑通；微信和钱包登录至少做出入口和交互流程，哪怕暂时对接的是测试环境或占位逻辑。

## 7\. 各板块详细需求（含本周落地程度标注）



> 说明：以下每个板块的"三态"指过去/进行中/即将，用一套统一的 Tab \+ 筛选组件复用，不用每个板块单独写一套。
> 
> 



### 7\.1 课程



**列表字段**：分类（AI 应用/AI Agent/FDE/AI 短剧/Web3 技术）、难度（入门/中级/进阶）、价格（免费/付费）、形式（直播/录播/训练营）、状态（过去/进行中/即将，按时间自动判断，不需要人工维护）。



**列表页**：卡片布局，每张卡片含封面图（用设计师提供的渐变色块\+课程名占位，不强求真实拍摄图）、分类标签、状态点、标题、价格。



**详情页**：封面 \+ 标题 \+ 讲师信息 \+ 课程大纲 \+ 报名按钮\+报名表单（姓名/邮箱/手机号/年龄/学历/职业/地区/来源/）。免费课程报名按钮直接跳转到对应的 B站/YouTube/视频号外链；付费课程点击后进入支付流程（见第 8 章）。



**本周目标**：列表\+详情页功能完整，内容先用你现有的《TinTin AI Agent实战训练营》等已知课程信息填充，其余历史课程先做"卡片\+跳转外链"的最简版本（详见 7\.6）。



### 7\.2 活动（独立板块，不与黑客松合并）



**理由**：活动是内容型运营（Meetup/AMA/大会/中国行），黑客松是竞赛型产品（团队/赛道/评审/奖金），字段和报名流程完全不同，合并会让筛选器混乱。但首页"最新动态"区域会把两者放在一起滚动展示，兼顾用户浏览习惯。



**列表字段**：类型（线上/线下/混合）、城市、标签（AMA/Workshop/Meetup/Party/Tour）、状态。



**详情页**：活动信息 \+ 报名表单（姓名/邮箱/手机号/公司/职位/来源/，场景化字段见第 6 章补充说明）。



**本周目标**：列表\+详情页功能完整，历史活动用"卡片\+跳转 Luma 外链"的方式呈现（见 7\.6），当前及未来活动录入真实报名表单。



### 7\.3 黑客松（独立板块）



**列表字段**：主题（Web3/AI/AI×Web3）、奖金池区间、报名截止时间、状态。



**卡片突出展示奖金池数字**（视觉上做大字处理，这是黑客松板块最吸引眼球的信息）。



**详情页**：奖金池 \+ 赛道说明 \+ 评审标准 \+ 报名表单（团队名/成员/GitHub/想参加的赛道）。



**本周目标**：列表\+详情页功能完整，历史黑客松同样先做"卡片\+跳转外链"。



### 7\.4 招聘



**列表字段**：角色（工程/运营/BD/设计/AI）、公司、城市、是否远程。



**详情页**：JD \+ 投递表单（简历上传/邮箱/GitHub）。



**本周目标**：功能完整，内容先由运营手动录入当前在招岗位，数量不用多，几个真实岗位即可。



### 7\.5 Token Hub（本周应给较高优先级，因为已有明确合作方）



因为你确认"已经有明确的合作方/渠道商"，这个板块的商业价值明确，**本周应该分配比原计划更多的时间**，而不是像其他新业务线一样先做占位页。



三个模块：



1. **渠道介绍**：横向卡片展示已确认合作的大模型厂商/渠道（每张卡片：logo \+ 支持的模型 \+ 起价 \+ 对接方式）；

2. **充值/对接流程说明**：充值以及部署教程

3. **API/用量信息**



### 7\.6 历史内容迁移（课程/活动/黑客松通用方案）



**分三步走，本周只做第一步：**



1. **第一步（本周做）**：把过去的课程/活动/黑客松整理成卡片——标题、封面图、时间、一句话简介——展示在对应板块，详情页有个显眼按钮"去 B站/YouTube/Luma 观看原始内容"直接跳转过去。这一步不需要真实搬运视频/内容，只需要运营整理一份表格数据，开发做一个通用的"外链卡片"组件即可复用在课程/活动/黑客松三个板块。

2. **第二步（V1\.1 做）**：接 YouTube/B站/Luma 的开放接口，自动同步新发布的内容生成卡片草稿。

3. **第三步（长期）**：只把效果最好的内容（比如 AI Agent 训练营）迁移到官网自建播放器和报名系统。

    

**本周目标**：通用外链卡片组件做完，运营整理至少 20\-30 条历史内容的表格数据先填充进去，验证展示效果，剩下的内容可以上线后逐步补充，不影响主线功能。



### 7\.7 应用工具



**两类标签**：代理产品（云厂商代理，主推）\+ 社区作品（社区自研，曝光用）。



**本周目标**：先做占位页——一个统一的卡片列表 \+ "申请上架"联系表单，真实产品数据可以先放 1\-2 个示例，运营后续持续补充，不阻塞主线开发。



### 7\.8 企业服务



三张卡片：AI 转型咨询 / 生态合作 ToB / 云与 Token 代理，每张卡片一句话介绍 \+ 联系表单入口。



**本周目标**：静态页面 \+ 联系表单，这块内容简单，优先级可以放在课程/活动/黑客松/登录/Token Hub 之后。



### 7\.9 关于我们 / 联系我们



团队介绍 \+ 发展历程（2018\-2026）\+ 数据背书（30万\+开发者/$370万\+奖励/200\+活动/800\+项目）\+ 联系表单 \+ 社交媒体链接（X/Telegram/Bilibili/Medium/YouTube/Discord）。



**本周目标**：静态页面，内容直接用你之前提供的对外介绍文案，改动量很小，优先级靠后但成本也低，建议顺手做完。

## 8\. 支付方案：三层递进，本周只做第一层



**结论：本周只做第一层，第二、三层留给 V1\.1 及以后。**



**第一层（本周做，几乎零开发成本）**：付费课程/活动的下单页展示你现成的**工商银行聚合收款码**（支持微信/支付宝/银联/数字人民币），用户扫码付款后点击"我已支付"按钮，订单状态变为"待核实"，运营在后台人工核对到账（对照工行商户流水），核实后系统自动弹出/发送"课程或活动顾问微信联系码"给用户。



**第二层（V1\.1，等订单量上来再做）**：接微信支付/支付宝官方接口，实现自动核销，不再需要人工核对。



**第三层（更长期，面向海外/Web3 用户）**：Stripe（海外信用卡）\+ 稳定币收款（Web3 用户）。



**免费内容**：不涉及支付，报名按钮直接跳转到对应第三方平台。



**Token Hub 的支付**：如第 7\.5 章所说，本周走"提交意向单\+人工对接"，不接自动扣费。



**本周目标**：付费课程/活动的下单流程（展示收款码→用户点击已支付→订单进入待核实列表→运营在后台手动标记已核实→自动发放顾问联系码）必须完整跑通一次。

## 10\. 技术栈建议（面向 vibe coding \+ 一周交付的场景优化）



|层|选型|为什么适合这次的约束条件|
|---|---|---|
|前端框架|Next\.js（App Router）\+ TypeScript|生态成熟，AI 辅助编码（vibe coding）对 Next\.js 的支持和训练数据都最充分，能显著提速|
|UI 组件|Tailwind CSS \+ shadcn/ui|开箱即用的组件库，不需要设计师产出完整组件规范，开发可以先用默认样式垫上，之后统一换色|
|数据库/后端|Supabase（Postgres \+ Auth \+ Storage 一体）|一个服务解决数据库、登录鉴权、文件存储三件事，一周时间不用再单独搭后端服务|
|部署|Vercel|一键部署，域名接入和 CDN 都是现成的，不用自己配运维|
|AI（V1 假路由）|纯前端/轻后端规则引擎，无需接外部大模型 API|零延迟、零调用成本，且逻辑简单，一天内能完成|
|微信登录|微信开放平台网页授权|如果本周资质审核来不及，先做 UI 占位，接口留空|
|钱包登录|wagmi \+ 单一钱包（MetaMask）优先|一周内只支持一种钱包已经足够验证登录路径，多钱包支持放 V1\.1|



**本周目标**：技术选型不要中途更换，一旦定下就不再犹豫，vibe coding 的效率优势建立在"用主流、文档丰富的技术栈"基础上，冷门选型会拖慢 AI 辅助编码的效果。

## 11\. 视觉与品牌规范（本周产出的是"第一版"，非最终版）



- **底色**：浅色系为主，大量留白，不做深色系；

- **强调色**：一个主色（建议紫色系）\+ 一个辅助渐变色，D1 就要定下具体色值；

- **Logo**：先做文字方案（TinTin 字样 \+ 简单图形标记），不强求复杂的几何线条设计，够用即可，后续可以迭代；

- **吉祥物**：胖狗 TinTin，第一版用静态插画（3 个表情：默认/眨眼/打招呼），不做动画，V1\.1 再升级 Lottie 动效；

- **字体**：中文思源黑体，英文 Inter；

- **整体调性**：几何、简约、有科技感，避免堆砌币圈土味元素（比如夸张的霓虹色、火箭表情包一类）。
