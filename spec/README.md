## 1\. 项目背景与目标



- TinTinLand：2018 年创立，华语最大 Web3 开发者社区，2026 年开始拓展 AI 方向业务。

- 核心资产：30 万\+ 开发者、220\+ 高校、50\+ 公链官方合作、800\+ 项目孵化、累计发放奖励 $370万\+。

- 2026 年新业务线（本次官网必须承接）：课程（FDE / AI 短剧 / AI 应用等）、企业服务（AI 转型咨询）、Token Hub（AI 大模型 token 代理/分销，**已有明确合作渠道商**）、代理云厂商产品分销。

- 官网核心目标：**让第一次来访的人在 10 秒内看懂"我是谁、这里能给我什么、下一步点哪里"**，同时把过去分散在 B站/YouTube/Luma/Notion 的历史内容和未来的新内容统一到官网入口。

- 视觉基调：品牌资产目前基本空白，本次项目**顺带完成品牌视觉的第一版**（Logo、胖狗吉祥物、配色规范），不是等品牌做完才开始开发，而是设计师和开发并行推进（见第 3 章协同机制）。

## 3\. 一周落地机制：设计师与开发如何并行，不互相卡进度



这是本项目能不能一周做完的关键，单独拿一章说清楚。



**核心原则：设计师"抢跑"半天到一天，用最小可交付单位喂给开发，不要等"全套设计规范"做完才给。**



推荐节奏：



|时间|设计师产出|开发承接的动作|
|---|---|---|
|D1 上午|3 个配色方案草图 \+ Logo 文字方案（哪怕先是纯文字排版），敲定一个|开发先搭项目骨架、路由、导航栏结构，用系统默认灰色调过渡|
|D1 下午\-D2|敲定的配色出成 Design Token（背景色/主色/文字色/圆角/间距的具体数值，一张表就行，不用整套 Figma 组件库）|开发把 Design Token 接入 Tailwind 配置，全站换色|
|D2\-D3|胖狗吉祥物草图（3 个静态表情：默认/眨眼/打招呼即可，不强求动画）|开发先用几何图形占位（比如一个圆形\+简单表情）接入悬浮球逻辑，等吉祥物图出来直接替换图片，不改代码结构|
|D3\-D5|各板块卡片视觉细化（课程卡/活动卡/黑客松卡样式）|开发这几天在做数据结构和列表/详情页逻辑，卡片视觉随时可以插进去，不影响功能开发|
|D5\-D7|补细节、走查、动效微调|开发收尾、测试、部署|



**关键要求**：吉祥物动画**第一版可以不做**，用静态图 \+ CSS 简单过渡（呼吸感用 CSS 缩放动画就够，不需要 Lottie），这样不会因为等动画素材卡住开发主线。动画效果留在 V1\.1 用 Lottie 升级。



**本周目标**：设计师本周产出的是"够用的第一版视觉规范"，不是最终品牌手册；开发不因为等设计而空转超过半天。

## 5\. 首页设计：假 AI 对话路由（V1 核心亮点）



### 5\.1 为什么先做"假 AI"而不是接真大模型



一周时间，接真实大模型意味着要处理 prompt 设计、上下文管理、失败兜底、内容安全过滤等一整套工程问题，风险极高。**"假 AI"本质是一套规则引擎 \+ 预设话术库**，用户体验上依然是"打字或点选项→立刻给出结构化答案和行动按钮"，只是背后没有大模型推理，而是关键词匹配 \+ 预置的意图卡片。这个方案能在 1\-2 天内做完，且**代码结构和真 AI 接口保持一致**，V1\.1 换成真大模型时只需要替换后端逻辑，前端不用重做。



### 5\.2 交互设计



```Plain Text
┌──── Hero（首屏） ─────────────────────────────┐
│         [胖狗 TinTin 静态图，打招呼姿势]           │
│         Hi，我是 TinTin，来帮你找路              │
│                                                │
│    ┌──────────────────────────────────┐       │
│    │ 💬 想学点 / 想打场 / 想找工作…         │       │
│    └──────────────────────────────────┘       │
│                                                │
│  [推荐一门课] [最近黑客松] [找生态工作]           │
│  [了解 Token Hub] [随便看看]                    │
└────────────────────────────────────────────────┘
```



- 用户点击任一 chip 或输入包含关键词的文字（比如"课程""学习""AI"→ 匹配课程意图；"黑客松""比赛""奖金"→ 匹配黑客松意图；"工作""招聘""岗位"→ 匹配招聘意图；"token""充值""大模型"→ 匹配 Token Hub 意图）；

- 匹配后**直接返回结构化卡片**：一句话说明 \+ 1\-2 个具体推荐内容（比如具体某门课）\+ 明确的行动按钮（"报名这门课" / "查看黑客松详情"），不是泛泛的"了解更多"；

- 无法匹配到任何关键词时，兜底话术："这个我还没学会，你可以直接看看下面这些板块，或者留言联系我们的团队"，附上四个板块入口和联系表单链接；

- 首屏下方保留 4 个身份分流卡（开发者 / 项目方 / 求职者 / 随便看看），给不想打字的用户一个更直接的路径，点击后同样触发对应的规则匹配结果。

    

### 5\.3 全站悬浮胖狗



- 除首页外的其他页面，右下角常驻一个胖狗头像悬浮球（V1 用静态图 \+ CSS 呼吸动效，不用等动画素材）；

- 点击展开一个简化对话面板，复用首页的同一套规则引擎，让用户不管在哪个页面都能问"怎么报名""怎么充值"这类问题；

- **本周目标**：假 AI 路由能覆盖课程/活动/黑客松/招聘/Token Hub 五个核心意图 \+ 一个兜底方案；悬浮球在所有页面正常展开/收起。V1\.1 目标：换成真实大模型 \+ 上下文记忆。

## 6\. 登录方案



### 6\.1 首次注册/登录：三选一，零填表（本周主力方案）



**首次注册/登录只提供 3 种方式，且都做到几秒内完成，不要求填写任何额外资料：**



|方式|交互|本周优先级|
|---|---|---|
|邮箱验证码|输入邮箱 → 收验证码 → 直接登录，不设密码|**必须做，本周主力方案**|
|微信一键登录|扫码/跳转授权|本周做，如果微信开放平台资质/审核来不及，先做 UI 入口，接口留空放 V1\.1|
|Web3 钱包签名登录|连接钱包签名一次，无需转账无 gas|本周做基础版（MetaMask 一种钱包即可），放在邮箱下方的小字链接，位置低调|



**明确不做的事**：注册环节不要求手机号、不要求实名、不要求填职业/公司。这些信息挪到"报名课程/活动/黑客松/投递简历"的那一刻才通过场景化表单收集，一次填写后写入用户档案，下次自动带出。



### 6\.2 按用户地域/身份分层的登录方式优先级建议



除上述三种"本周必做"方式外，从海内外用户维度补充以下登录方式的优先级建议，供 V1\.1 排期参考：



|用户群体|推荐登录方式|优先级|
|---|---|---|
|全体用户|邮箱验证码|P0，本周必须做|
|国内开发者/学员|微信登录|P1，本周做|
|海外开发者/求职者|GitHub 登录|P1，建议提升至与微信同批（额外价值：可直接复用于招聘板块的身份验证与主页信息抓取）|
|Web3/加密社区用户（含海外）|X 登录、Telegram 登录|P2，可放 V1\.1|
|Web3 钱包用户|钱包签名登录（见 6\.1）|已确定，不在本次讨论范围|



### 6\.3 微信登录实现步骤（保姆级）



|步骤|操作|备注|
|---|---|---|
|1|注册微信开放平台账号（open\.weixin\.qq\.com），使用未被其他微信平台绑定的邮箱|—|
|2|账号中心 → 开发者资质认证 → 申请企业认证（个人主体通常无法申请网页登录能力）|需营业执照、法人身份信息，费用 ¥300，审核数个工作日至一周|
|3|认证通过后创建"网站应用"，填写应用名称/简介/图标/官网地址|—|
|4|配置"授权回调域"为官网实际域名|配置错误会导致登录跳转失败|
|5|提交应用官方审核|建议提前完成隐私政策/用户协议页面|
|6|审核通过后获取 AppID 与 AppSecret|AppSecret 仅可存于后端，不可写入前端代码|
|7|开发对接 OAuth2\.0 网页授权流程：用户点击登录 → 跳转微信授权页（带 AppID\+回调地址）→ 用户扫码确认 → 微信跳转回调地址并带 code → 后端用 code 换取 access\_token/unionid → 建立登录态|预计开发工作量：1\-2 人日|
|8|若本周资质审核未完成|先上线登录按钮 \+ 交互 UI，接口留空或提示"敬请期待"，待资质通过后接入真实逻辑，不阻塞主线|



**本周目标**：邮箱验证码登录必须跑通；微信和钱包登录至少做出入口和交互流程，哪怕暂时对接的是测试环境或占位逻辑；GitHub/X/Telegram 登录纳入 V1\.1 排期，本周不作为必做项。

### 7\.1 课程



**列表字段**：分类（见 7\.1\.1 课程分类体系）、难度（入门/中级/进阶）、价格（免费/付费）、形式（直播/录播/训练营）、状态（过去/进行中/即将，按时间自动判断，不需要人工维护）。



**列表页**：卡片布局，每张卡片含封面图（用设计师提供的渐变色块\+课程名占位，不强求真实拍摄图）、分类标签、状态点、标题、价格。



**详情页**：封面 \+ 标题 \+ 讲师信息 \+ 课程大纲 \+ 报名按钮。免费课程报名按钮直接跳转到对应的 B站/YouTube/视频号外链；付费课程点击后进入支付流程（见第 8 章）。

### 7\.2 活动（独立板块，不与黑客松合并）



**理由**：活动是内容型运营（Meetup/AMA/大会/中国行），黑客松是竞赛型产品（团队/赛道/评审/奖金），字段和报名流程完全不同，合并会让筛选器混乱。但首页"最新动态"区域会把两者放在一起滚动展示，兼顾用户浏览习惯。



**列表字段**：类型（线上/线下/混合）、城市、标签（AMA/Workshop/Meetup/Tour）、状态。



**详情页**：活动信息 \+ 报名表单（字段规范见下）。



#### 7\.2\.1 活动报名表单字段规范



同 7\.1\.2，必选/可选默认值由运营在活动上架时可调整，是否需要审核同样由运营配置。



|字段|默认建议|说明|
|---|---|---|
|姓名|必选|—|
|邮箱|必选|—|
|手机号|必选|—|
|公司|可选|运营可按活动类型（如 ToB 生态合作论坛）在上架时改为必选|
|职位|可选|同上，由运营在上架时决定|
|来源|系统自动记录|同 7\.1\.2|

## 8\. 支付方案



### 8\.1 合规风险判断（供决策参考，非法律意见）



> 本节为公开监管信息整理，不构成法律意见。带 ⚠️ 标记的条款建议在执行前经律师书面确认。
> 
> 



|事项|风险判断|依据|
|---|---|---|
|宣传 Web3 技术活动本身（技术分享/黑客松/培训）|本身不构成违法，但可能被归类为"特殊行业"，ICP 备案审核标准更严|备案通常审核网站内容与"服务项目"是否一致|
|若活动涉及不当层级返利、拉人头奖励机制|⚠️ 存在被认定为违法组织活动的风险，应完全避免此类机制|公开司法解读：以新技术概念包装的层级返利模式可能触及相关刑事红线|
|销售/代理海外 AI 大模型 Token（Token Hub 业务）|⚠️ 风险级别高于官网本身，2026 年已有真实处罚案例|未取得 ICP 许可证从事经营性增值电信业务；用户数据未经安全评估出境；收费与下游用途挂钩时存在相关刑事风险|



**建议**：Token Hub 业务模式（渠道商资质、资金流向、用户数据是否出境）应单独委托律师做专项合规评估，与官网整体支付方案的决策分开处理。



### 8\.2 三条支付路径（供决策参考）



**路径 A：走 ICP 备案路线，接入国内官方支付接口**



|步骤|操作|预计周期|
|---|---|---|
|1|确认网站主办单位为国内有效存续公司主体（个人备案域名无法开通微信支付商户号）|—|
|2|向服务器/CDN 服务商提交 ICP 备案（营业执照、法人身份证、网站负责人信息、域名证书），如实填写"服务项目"|15\-20 个工作日|
|3|判断是否需额外申请经营性 ICP 许可证（网站涉及在线支付/会员付费，如课程活动收费，大概率需要）|1\-3 个月|
|4|备案通过后，向微信支付商户平台/支付宝开放平台提交商户号申请（需备案截图、经营场所证明、对公账户信息；商户主体与 ICP 备案主体不一致需补充合作协议或集团关系证明）|视审核|
|5|商户号通过后，在商户平台开通 H5 支付/Native 扫码支付权限，提交支付域名及该域名的备案截图|视审核|
|6|开发按微信支付/支付宝官方 API 文档，接入统一下单接口 \+ 支付结果异步通知接口|视开发排期|
|7|沙箱环境验证下单\-支付\-回调\-发货完整流程后切换生产环境|—|



**路径 B：不走备案路线（境内主体 \+ 第三方聚合收款）**



沿用现有工行聚合收款码模式，或接入持牌第三方聚合支付服务商（以商户身份入驻，不需自行申请 ICP 许可证）。仍需完成基础 ICP 备案（服务器国内托管的强制要求）。优点：接入快（数天至两周）。缺点：有交易手续费（约 0\.3%\-0\.6%），限额可能低于自建商户号。



**路径 C：境外主体 \+ 境外支付（Stripe / 稳定币）**



注册境外公司主体（新加坡/香港/美国），服务器部署境外，接入 Stripe 或 PayPal。不受国内 ICP 备案约束。风险：境内用户访问境外服务器速度下降（无国内 CDN），境内用户用境外支付渠道存在外汇合规限制，非所有境内银行卡可顺利完成 Stripe 支付。适合以海外用户/Web3 用户为主的业务线。



**⚠️ 待老板决策：业务隔离方案（路径 B \+ 路径 C 组合，尚未确认）**



|业务线|支付路径|主体|
|---|---|---|
|课程 / 活动（境内用户为主）|路径 B（第三方聚合收款，过渡期不做完整 ICP 许可证）|境内公司主体|
|Token Hub（海外用户/Web3 用户）|路径 C（Stripe \+ 稳定币）|境外公司主体，单独隔离，避免合规风险牵连主站|



> **此方案是 Claude 的建议方向，尚未经老板确认，老板明确表示"支付问题再思考"，在最终决策前不作为开发依据，本周仍执行第 8\.3 章的第一层现有方案。**
> 
> 



### 8\.3 本周执行方案：三层递进，本周只做第一层



**第一层（本周做，几乎零开发成本）**：付费课程/活动的下单页展示你现成的**工商银行聚合收款码**（支持微信/支付宝/银联/数字人民币），用户扫码付款后点击"我已支付"按钮，订单状态变为"待核实"。**用户下单后系统立即自动发放"课程或活动顾问微信联系码"**（前置到下单环节，而非等待核实完成，让用户先主动添加运营顾问，通过联系码与订单号快速核对到账，缩短用户等待感知时间），运营在后台人工核对到账（对照工行商户流水），核实后将订单标记为已核实（此时不再重复触发发码动作，仅更新状态）。若联系码自动发送失败，运营可在后台手动补发。



**第二层（V1\.1，等订单量上来再做）**：接微信支付/支付宝官方接口（对应 8\.2 路径 A），实现自动核销，不再需要人工核对。



**第三层（更长期，面向海外/Web3 用户）**：Stripe（海外信用卡）\+ 稳定币收款（Web3 用户），对应 8\.2 路径 C。



**免费内容**：不涉及支付，报名按钮直接跳转到对应第三方平台。



**Token Hub 的支付**：如第 7\.5 章所说，本周走"提交意向单\+人工对接"，不接自动扣费。



**本周目标**：付费课程/活动的下单流程（展示收款码→用户点击已支付→系统立即发放顾问联系码→订单进入待核实列表→运营在后台手动标记已核实）必须完整跑通一次；8\.2 章的合规路径选择与业务隔离方案暂不执行，等待老板最终决策。

## 11\. 视觉与品牌规范（本周产出的是"第一版"，非最终版）



- **底色**：浅色系为主，大量留白，不做深色系；

- **强调色**：一个主色（建议紫色系）\+ 一个辅助渐变色，D1 就要定下具体色值；

- **Logo**：先做文字方案（TinTin 字样 \+ 简单图形标记），不强求复杂的几何线条设计，够用即可，后续可以迭代；

- **吉祥物**：胖狗 TinTin，第一版用静态插画（3 个表情：默认/眨眼/打招呼），不做动画，V1\.1 再升级 Lottie 动效；

- **字体**：中文思源黑体，英文 Inter；

- **整体调性**：几何、简约、有科技感，避免堆砌币圈土味元素（比如夸张的霓虹色、火箭表情包一类）。

## 14\. 运营后台功能规范（对应第 4 章路由结构中的 `/admin`）



### 14\.1 设计原则



后台按"运营人员的工作流"划分模块，不按前台板块拆分独立后台页，避免运营在多个入口之间往返操作。



### 14\.2 模块一：内容管理中心



覆盖课程 / 活动 / 黑客松 / 招聘 / 应用工具 / Token Hub 渠道六类内容，统一采用「列表 → 新建 → 编辑 → 上下架 → 删除」的标准操作链路。



|功能点|说明|本周优先级|
|---|---|---|
|内容来源切换|新建内容时首先选择 `content_source`：站内自建（native）或外链第三方平台（external\_link），对应第 9 章数据结构|必须|
|站内自建表单|选择 native 后展开完整字段（标题/封面/详情/分类/报名表单等，按板块不同）|必须|
|外链内容表单|选择 external\_link 后表单精简为：标题、封面、简介、外链地址四项|必须|
|上下架开关|独立于删除操作的状态开关，用于临时下线保留数据|必须|
|报名表单审核开关|运营在内容上架时选择该内容的报名/投递是否需要人工审核。部分课程/活动/黑客松为完全开放性质，任何人均可报名参加，此时表单收集的目的是建立用户数据库，不需要审核环节；需要筛选（如限定名额、需资质审查）的内容则开启审核|必须|
|表单字段必选/可选配置|报名/投递表单每个字段的"是否必选"由运营在该内容上架时自行设置，而非系统固定规则，对应第 7\.1\.2/7\.2\.1/15 章表单字段规范|必须|
|封面图裁剪预览|按板块卡片的固定比例做裁剪预览，避免尺寸错误导致前台变形|建议本周做|
|批量导入|Excel 模板批量导入，用于第 7\.6 章历史内容迁移（20\-30 条数据）|建议本周做|
|修改日志|记录创建人/修改人/修改时间，用于团队变大后的问题排查|可放 V1\.1|



### 14\.3 模块二：首页运营位管理



|功能点|说明|
|---|---|
|合作项目 Logo 墙|支持增删、拖拽排序|
|首页 Hero 内容|支持替换焦点图/文案|
|"最新动态"手动置顶|不完全依赖时间自动排序，支持运营手动将指定内容顶到最前|



### 14\.4 模块三：报名 / 投递审核中心



统一审核队列，覆盖课程报名、活动报名、黑客松报名、招聘投递（企业发布审核 \+ 人才信息审核）。仅对开启了"报名表单审核开关"（见 14\.2）的内容生效。



|功能点|说明|
|---|---|
|按类型筛选|可按内容类型/状态筛选审核队列|
|批量通过/拒绝|减少逐条操作成本|
|导出 Excel|用于活动/黑客松现场签到|



### 14\.5 模块四：订单与支付核销（对应第 8 章）



|功能点|说明|
|---|---|
|待核实订单列表|展示状态为 `pending_review` 的订单；**用户下单后立即自动发放顾问联系码**（前置到此环节，而非等待核实完成后才发放），让用户先主动添加运营顾问微信，通过联系码与订单号快速核对到账，缩短用户等待感知时间|

### 15\.3 隐私展示规则（人才信息板块）



前台列表展示：昵称、工作经历/技能标签、期望方向、自我介绍等用户已填写的可选公开字段。简历/主页链接一经用户上传即视为同意对外展示，不需要额外的"沟通请求"授权流程。**唯一的例外是联系方式**：联系方式始终不在前台公开展示，企业方需通过平台发起联系请求，由系统代为触达用户填写的联系方式，避免用户的手机号/邮箱被直接抓取或滥用。



### 15\.4 隐私处理的统一原则（适用于课程/活动/黑客松）



报名时收集的手机号/邮箱等联系方式，默认仅对运营与审核可见；前台公开展示的内容（如黑客松参赛团队列表）仅展示团队名与成员昵称，不展示手机号/邮箱。此原则统一写入后台功能规范（对应第 14\.2 章），不在每个板块单独定义。



**本周目标**：企业招聘信息表单本周做完整；人才信息表单本周需在数据结构层面区分"公开展示字段"与"仅企业发起联系后触达字段"（联系方式），交互可以先做基础版，逐步完善。
